# SplitSpace — Microservices Code Structure

## 📌 Общая структура решения

Каждый микросервис в проекте представлен как отдельное **.NET Solution**, расположенное в корневом каталоге репозитория.

Примеры сервисов:
- `AuthService`
- `SpaceService`
- `FinanceService`
- `ApiGateway`

Каждый сервис является независимой единицей разработки и имеет собственную структуру кода, тестов и слоёв приложения.

---

## 📁 Структура микросервиса

Каждый микросервис содержит две основные папки:
```
/src
/tests
```


---

## 🧱 Папка `src`

Папка `src` содержит исходный код сервиса и включает несколько проектов:

```
SplitSpace.ServiceName
SplitSpace.ServiceName.Logic
SplitSpace.ServiceName.Dal
SplitSpace.ServiceName.Common
SplitSpace.Grpc
```


---

## 📌 Описание проектов

### 🔷 SplitSpace.ServiceName (Main)

Основной проект сервиса.

Отвечает за:
- HTTP/gRPC endpoints (Controllers)
- маршрутизацию запросов
- подключение middleware
- конфигурацию приложения

👉 это точка входа в сервис

---

### 🔷 SplitSpace.ServiceName.Logic

Слой бизнес-логики.

Содержит:
- бизнес-сервисы (services)
- доменные модели
- бизнес-правила
- обработку сценариев использования

📌 Вызовы DAL происходят только из этого слоя.

---

#### 📁 Структура Logic слоя

```
/Services
    /Implementations
    # тут находятся интерфейсы
```


- `Implementations` — реализации сервисов  

---

### 🔷 SplitSpace.ServiceName.Dal

Слой доступа к данным.

Содержит:
- репозитории
- DbContext (если используется EF Core)
- SQL-запросы / ORM-логика

#### 📁 Структура Dal слоя

/models
    /entities # модели полностью отражающие сущности в базе данных
    /dto # например модели для вставки или обновления отдельных полей
/repositories
    /Implementations # тут находятся реализации
    # тут находятся интерфейсы

📌 Используется только Logic слоем

---

### 🔷 SplitSpace.ServiceName.Common

Общий слой сервиса.

Содержит:
- enums
- константы
- общие утилиты

📌 используется во всех слоях сервиса

---

### 🔷 SplitSpace.Grpc

Проект, содержащий:
- proto файлы
- контракты взаимодействия между микросервисами

Используется для синхронного межсервисного взаимодействия.

#### 📁 Структура Grpc слоя

/Protos/{ServiceName} # протофайлы конкретного сервиса
                    /api # gRPC сервисы
/generated # сгенерированные c# классы

---

## 🧪 Папка `tests`

Каждый микросервис содержит отдельный проект тестов:

SplitSpace.ServiceName.UnitTests


Содержит:
- unit tests
- все тесты должны находиться в папке tests проекта UnitTests

---

## 🧠 Архитектурные принципы

### 🔷 1. Разделение слоёв

- Main → API слой
- Logic → бизнес-логика
- Dal → доступ к данным
- Common → общие модели

---


Корневой namespace каждого сервиса:
SplitSpace.{ServiceName}
