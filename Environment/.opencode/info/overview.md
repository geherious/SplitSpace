# SplitSpace — Backend System Overview

## 📌 Общая информация

**SplitSpace** — это серверная часть системы управления личными и групповыми финансами, разработанная с использованием микросервисной архитектуры.

Система позволяет пользователям:
- вести учет личных и групповых расходов;
- делить расходы между участниками;
- отслеживать задолженности;
- анализировать финансовую активность.

---

## 🏗 Архитектура

Проект реализован в виде набора микросервисов, каждый из которых отвечает за свою область данных и логики.

### Основные сервисы:

| Сервис | Описание |
|-------|--------|
| **ApiGateway** | Точка входа в систему, маршрутизация запросов |
| **AuthService** | Аутентификация, пользователи, токены |
| **SpaceService** | Управление пространствами, участниками и ролями |
| **FinanceService** | Расходы, счета, сплиты, долги |

---

## 📂 Структура репозитория
```
/SplitSpace
/ApiGateway # API Gateway (routing, aggregation)
/AuthService # Пользователи и аутентификация
/SpaceService # Пространства и участники
/FinanceService # Финансовая логика
/Environment # Docker, конфигурация окружения, конфигурация opencode
```
---

## ⚙️ Технологический стек

- **Backend:** C#, ASP.NET Core
- **База данных:** PostgreSQL
- **Межсервисное взаимодействие:**
  - gRPC (синхронное)
  - Apache Kafka (асинхронное, события)
- **Контейнеризация:** Docker, Docker Compose

---

## 🔗 Взаимодействие сервисов

### Синхронное (gRPC)
Используется для:
- авторизации пользователя (AuthService)
- проверки принадлежности к пространству (SpaceService)

---

### Асинхронное (Kafka)
Используется для событий:

- `UserAddedToSpace`
- `UserRemovedFromSpace`
- `UserRoleChanged`

SpaceService публикует события → другие сервисы подписываются (например, FinanceService).

---

## 🧠 Основные принципы

- **Изоляция данных:** у каждого сервиса своя база данных  
- **Отсутствие внешних ключей между сервисами**  
- **Согласованность через события (event-driven)**  
- **UUID как идентификаторы**  
- **Горизонтальная масштабируемость (шардирование по space_id)**
